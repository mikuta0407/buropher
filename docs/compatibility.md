# Compatibility with Redmine 6.1.2

buropher aims to be a drop-in replacement for Redmine 6.1.2 for users, administrators and API
clients. Compatibility is checked by a differential test harness that sends the same requests to a
real Redmine 6.1.2 (loaded with Redmine's own test fixtures) and to buropher and compares the
normalized HTML/JSON/XML responses ([development.md](development.md#compatibility-harness)).
Every accepted difference is listed with a reason in
[`testdata/compat/allowlist.yml`](../testdata/compat/allowlist.yml).

## What is the same

- **URLs and routes**, including `.json`/`.xml` REST API, `.atom` feeds, `.csv` and `.pdf` exports,
  and the `/sys` web service.
- **HTML markup, CSS and JavaScript**: Redmine's stylesheets, images, JavaScript and the default
  themes are bundled unchanged (`web/assets`, synced from upstream), so pages look and behave the same
  and user scripts/bookmarklets keep working.
- **Translations**: Redmine's locale files are used as-is (all languages).
- **Text formatting**: Textile and CommonMark Markdown, macros, wiki links, syntax highlighting
  (Rouge-compatible lexers), with output matching Redmine's renderers.
- **Business rules**: permissions and roles, workflows and field permissions, issue visibility,
  custom fields, queries and filters, notifications and their recipients, time tracking,
  versions/roadmap, wiki history, forums, news, documents, files, calendar and Gantt.
- **API keys, feed keys and passwords** survive migration; Redmine password hashes are accepted and
  upgraded to Argon2id on first login.
- **Data model semantics**: IDs are preserved by the importer, so existing links keep working.

## Known deviations

| Area | Difference |
|---|---|
| Repositories | **Git only.** Subversion, Mercurial, CVS, Bazaar and Filesystem repositories are not supported; the SCM selection lists only Git. Imported non-Git repositories cannot be browsed. |
| Plugins | Redmine plugins (Ruby) are not supported, and plugin data is not migrated. Some popular needs are covered by built-in extensions (below). |
| *Administration > Information* | Shows buropher's version, Go version, database adapter etc. instead of the Ruby/Rails/ImageMagick checks. Layout and CSS classes are the same. |
| PDF export | Same pages, layout and file names, generated by a pure-Go engine. The result is a close approximation, not byte-identical; fonts differ unless configured ([pdf.md](pdf.md)). Gantt PNG export (`gantt.png`, which needs ImageMagick in Redmine) is not available. |
| Thumbnails | Image attachments only; no PDF thumbnails (Redmine needs ImageMagick/Ghostscript for those). |
| Empty strings | Empty text values are stored as `NULL` (see [schema.md](schema.md)). In the API, an empty attachment `description` is `null` in JSON and `<description/>` in XML; empty custom values behave like unset ones. |
| Role permissions in the API | `/roles/:id.json` lists permissions in Redmine's definition order, not in the order they were saved. |
| Ordering ties | Lists sorted only by timestamp (e.g. journals) use the ID as a tie-breaker, which may differ from the database-dependent order in Redmine when timestamps are equal. |
| Wiki history | Redmine's `wiki_contents` and `wiki_content_versions` are merged into one history table. If they disagree for the same version (only seen in test fixtures), the current content wins. |
| Time zone list | The UTC offsets shown in the time zone selector come from the generated zone table and can lag behind tzdata changes for a few zones. |
| Configuration | `config/configuration.yml`, `database.yml` and environment files are replaced by one TOML file plus environment variables ([configuration.md](configuration.md)). |
| Deployment | Sub-path deployment is supported with `server.relative_url_root` (Redmine's `RAILS_RELATIVE_URL_ROOT`); see [configuration.md](configuration.md#sub-path-deployment). |
| Rake tasks | Replaced by subcommands: `buropher reminders` (`redmine:send_reminders`), `buropher jobs run`, built-in schedulers for reminders and `fetch_changesets`. Other rake tasks (e.g. LDAP sync, attachment digest updates, plugin tasks) have no equivalent. |
| Sessions | Login sessions are not migrated from Redmine; users log in again once. |

## Extensions (not in Redmine)

- **LDAP** authentication enhancements.
- **Single sign-on** with OpenID Connect, including a Microsoft Entra ID preset and group
  synchronisation ([sso-entra-id.md](sso-entra-id.md)).
- **Discord DM notifications** in addition to e-mail ([discord.md](discord.md)).
- Built-in background job queue and schedulers (no cron needed).
- Single static binary, SQLite by default, PostgreSQL supported.

The extra UI elements are marked with the CSS class `buropher-extra`.

## Supported databases and sources

| | Supported |
|---|---|
| buropher database | SQLite, PostgreSQL |
| Migration source | Redmine 6.1.0 – 6.1.2 on MySQL/MariaDB, PostgreSQL, SQLite or SQL Server |
